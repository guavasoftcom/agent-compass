Retention

Nothing prunes old telemetry on its own. Pick a window to see what removing everything older would reclaim, then either run the SQL yourself or purge from here — the button deletes permanently, behind a confirmation.

Before you run this
  • A session is deleted only once it has no activity anywhere — logs, tokens, or traces — for the whole window above. A session with any recent activity keeps every row, including its oldest ones: sessions are never split between old and recent.
  • A DELETE makes the space reusable by Postgres but does not return it to the operating system. Only VACUUM FULL shrinks the files, and it takes an exclusive lock plus room for a full rewrite.
  • Inside a session that does get purged, the newest row of every metric counter is kept regardless of age, as a safeguard: if that session ever emitted again, its next value wouldn't be booked as one giant spike.
  • This is independent of Claude Code's own cleanupPeriodDays setting (default 30 days, controlling how long a session stays resumable locally) — purge more aggressively than that and a resumed session's history can already be gone from this dashboard even though the conversation itself still resumes fine.
Byte figures are proportional estimates, not measurements.
-- Deletes every session whose LAST activity, across logs, metrics, and traces, is -- older than 30 days (before 2026-07-24T16:04:58.746998Z). A session's rows are removed as a whole or not at -- all -- a row belonging to a still-active session survives however old it is. -- Reclaims roughly 5329309446 bytes, per the estimate on the Settings page. BEGIN; CREATE TEMP TABLE dormant_sessions_for_purge ON COMMIT DROP AS SELECT session_id FROM ( SELECT session_id, max(timestamp) AS last_seen FROM metric_points WHERE session_id IS NOT NULL GROUP BY session_id UNION ALL SELECT session_id, max(timestamp) FROM log_records WHERE session_id IS NOT NULL GROUP BY session_id UNION ALL SELECT session_id, max(start_timestamp) FROM spans WHERE session_id IS NOT NULL GROUP BY session_id ) activity GROUP BY session_id HAVING max(last_seen) < TIMESTAMP '2026-07-24T16:04:58.746998Z'; DELETE FROM metric_points mp WHERE (mp.session_id IN (SELECT session_id FROM dormant_sessions_for_purge) OR mp.session_id IS NULL AND mp.timestamp < TIMESTAMP '2026-07-24T16:04:58.746998Z') AND NOT EXISTS (SELECT 1 FROM metric_points newer WHERE newer.stream_id = mp.stream_id AND newer.timestamp > mp.timestamp); DELETE FROM log_records WHERE session_id IN (SELECT session_id FROM dormant_sessions_for_purge) OR (session_id IS NULL AND timestamp < TIMESTAMP '2026-07-24T16:04:58.746998Z'); DELETE FROM spans WHERE session_id IN (SELECT session_id FROM dormant_sessions_for_purge) OR (session_id IS NULL AND start_timestamp < TIMESTAMP '2026-07-24T16:04:58.746998Z'); COMMIT;

Run this while no agent is exporting
  • A session is only deleted once it has no activity anywhere — logs, tokens, or traces — for the whole window above. A session with any recent activity is left completely untouched, including its oldest rows: sessions are never split between "old, deleted" and "recent, kept".
  • The delete holds locks on all three tables for as long as it runs — on a large database, minutes. Telemetry arriving meanwhile can block behind it, and an exporter that gives up drops those events for good.
  • Every other page will shift underneath anyone reading it, mid-session.
  • 2.2K rows are kept despite being older than the cutoff — almost all of them because their session is still active elsewhere, plus one marker per counter inside a purged session as a safeguard: if that session ever emitted again, its next value wouldn't be booked as one giant spike.
  • Space is marked reusable, not returned to the disk. That needs a separate VACUUM FULL.
  • This is independent of Claude Code's own cleanupPeriodDays setting (default 30 days), which controls how long a session stays resumable locally. Purge more aggressively than that and a resumed session can show up with no history — its telemetry was already gone.
